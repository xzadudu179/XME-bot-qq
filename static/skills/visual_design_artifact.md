# 视觉设计 Artifact 生成

把"先规格后代码、写完必看"的方法论落成可交付的视觉作品。本技能源自"鹈鹕骑自行车"SVG 动画的完整实战迭代，规则全部踩过真实的坑，已泛化到各类视觉媒介。

## 产出定位

- 交付**自包含文件**：单文件 SVG / 单文件 HTML / 渲染出的 PNG。
- 质量标准是两层的：**结构正确**（连接、对齐、比例）+ **审美成立**（配色、构图、轮廓）。两者都只有渲染后才看得见——所以验证环节不可省略。

## 媒介路由（先选媒介再动笔）

| 需求特征 | 媒介 |
|---|---|
| 矢量插画 / 图标 / logo / 卡通场景 / 循环小动画；要嵌网页、无限缩放、单文件 | **单文件 SVG**（动画用纯 SMIL，不用 JS/CSS） |
| 交互效果 / 大量粒子与生成艺术（流场、噪声、元胞自动机）/ 复杂排版 | **单文件 HTML**（内嵌 CSS/JS/canvas） |
| 需要位图交付 | 先做矢量/HTML，再无头 Chrome 截 PNG |
| 报告、海报 PDF、幻灯片等文档 | 走对应 document 技能；本文的造型与配色原则照样适用 |

## 核心方法论：先规格后代码，写完必看

五阶段循环，跳过任何一步都会返工：

1. **设计规格**（纸面定案）：尺寸画布、风格档位、调色板、构图焦点、图层顺序
2. **结构推导**（纸面完成）：坐标系、原点部件、派生部件、关键公式——不边写边猜
3. **编写**：按图层清单施工，调色板当作 design token 先定义后引用
4. **渲染验证**：无头浏览器截图 + 目检清单（必做，几何错误写的时候看不出来）
5. **诊断迭代**：先隔离放大确诊 → 整体坐标变换修复 → 复渲染确认 → 清理临时文件

## 1. 设计规格（动笔前定案）

**调色板纪律**：3–5 色，角色分工明确（背景 / 主体 / 强调 / 阴影）；同一家族的饱和度与明度；需要变体时用"同色相加深或变浅"派生，**不引入新色相**。每个颜色都有职责，没有凑数的颜色。

**构图**：先定视觉焦点，再排其余；主体位置服从用户要求（如"放在画面左半部分"）；同类间距取等差形成留白节奏；用 前/中/后三层 + 投影 制造深度。

**造型一致性**：描边宽度分粗/中/细固定档位，全程取档不发明新值；圆角与端点风格统一；光源方向统一（所有阴影在同侧）；风格档位（扁平 / 描边卡通 / 线性）选定后贯彻到底。

## 2. 结构推导（几何先行）

- 先定**原点部件**（轮心、曲柄中心、髋点），其余位置从它们派生。
- 常用公式：圆周取点 `P = C + r·(cosθ, sinθ)`；关节 = 线段中点 + 前向偏移；**椭圆内判定**：点 (x,y) 在椭圆 (cx,cy,rx,ry) 内 ⟺ `((x−cx)/rx)² + ((y−cy)/ry)² < 1`。
- **图层清单**从后往前写出来再施工（天空 → 远景 → 地面 → 主体远侧件 → 结构 → 主体 → 近侧件）。z-order 错了，渲染后才发现会很贵。

## 3. 连接与轮廓完整性

- 子部件（尾巴、四肢、挂件、装饰）的**根锚点必须埋进父形状内部 15–20px**，不能搭在边缘上——搭边在代码里"看着挨着"，渲染出来就是断裂。每次挪动或缩放后重新用椭圆不等式验证。
- **剪影测试**：想象整个主体填成单色剪影，仍能认出它是什么——认不出就回去改造型。
- **有机形体（云、蓬松物、烟雾）构造规则**：一个平底大椭圆当唯一的底部轮廓，凸瓣只长在顶部，且任何瓣的下缘不得越过基底局部下缘。反例实录：4 个椭圆随手堆叠，最大椭圆占据顶部整条弧线、底部两瓣错位下垂 → 渲染成"上下颠倒的云"，用户一眼指出。

## 4. 运动一致性（动画类作品）

核心法则：

- **传送带法则**：地面上一切离散物（虚线、草丛、花）必须与路面**同速**反向移动，`v = 周期长度 / 时长` 逐项核算；装饰平铺循环 `dur = 平铺宽度W / v` 与虚线**严格相等**；轮面速度 `2πr/dur` 与地面差 ≤15%。静止的草 + 移动的虚线 = 用户会抱怨"像传送带"。
- **同步法则**：联动的多部件用同一 `dur`、同一起点相位（远侧肢体 +180°）。
- **无缝循环**：`dashoffset` 位移恰好一个周期；平铺平移恰好一个宽度 W；同类元素用负 `begin` 错峰。
- **横向无限延长的物体不要画出尽头**（路面、流水带、传送线）。

## 5. 整体挪位 / 改尺寸检查单

移动一个部件 = 对它的**每一个数字**做同样的 (dx, dy)。最容易漏的四处：

1. `animate` 的 `values` / `path` 帧列表——**每一帧**都要改（9 帧的腿是 9 组坐标）
2. `animateTransform rotate` 的圆心（`from="0 350 399"` 里的 350,399）
3. 外层 `transform="translate(...)"` 包装和 `<use x= y=>`
4. 配套的阴影、strap 等附属件

挪完回到第 3 节，重新验证连接锚点。

## 6. 反模式清单（都真实翻过车）

| 症状 | 根因 | 修复 |
|---|---|---|
| 云朵上下颠倒 | 椭圆随手堆，最大椭圆占顶部 | 平底椭圆 + 顶部凸瓣 |
| 尾巴看起来断开 | 根部顶点在父形状边缘外 | 锚点埋入 15–20px + 椭圆不等式验证 |
| 路面像传送带 | 虚线动、草花静止 | §4 同速滚动 + 无缝平铺 |
| "无限的路"有尽头 | 路面只画到 x=650 | 横贯全画布，装饰用平铺循环表现无限 |
| 配色显脏/显乱 | 色相过多、饱和度不成家族 | 3–5 色 + 角色分工 + 派生变体 |
| 画面"散" | 无焦点、间距随意 | 定焦点 + 等差留白节奏 + 三层深度 |
| 生成感廉价 | 描边宽度随手、光源方向混乱 | 固定描边档位 + 统一光向 + 剪影测试 |
| 腿和踏板穿帮 | dur 不一致或相位错位 | 同 dur + 同起点相位（远侧 +180°） |
| 挪位后作品散架 | 只改了静态坐标 | §5 检查单，values 帧和 rotate 圆心必查 |
